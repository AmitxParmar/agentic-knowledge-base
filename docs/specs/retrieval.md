# Spec: Hybrid Retrieval

## Purpose
Turn a question into a ranked list of evidence chunks, each carrying enough
reference information to become a citation.

## Dependencies
ADR-002 (Turbovec), ADR-003 (Model Gateway, for the rewrite step),
`schema.md` (`chunks`).

## Scope
The retrieval pipeline only — three stages, described below. Called by the
Research Agent as its one MVP tool (`docs/specs/researcher.md`); not a
standalone agent.

## Pipeline Stages

### 1. Query Rewrite (HyDE)
| | |
|---|---|
| Input | The raw question |
| Output | A hypothetical answer, generated by a local model via the Model Gateway |
| Why | A hypothetical answer sits closer in embedding space to real answer chunks than the bare question does — improves recall before search even runs |

### 2. Hybrid Search + Reciprocal Rank Fusion
| | |
|---|---|
| Input | The HyDE-expanded query, `workspace_id` |
| Output | A fused, ranked candidate list of chunk references with scores |
| How | Postgres pre-filters by metadata (workspace, document) into an ID allowlist. That allowlist is passed into Turbovec's dense search so filtering happens inside the scoring kernel. In parallel, Postgres full-text search (`tsvector`) runs BM25 keyword matching over the same allowlist. The two ranked lists are merged via Reciprocal Rank Fusion |

### 3. Rerank
| | |
|---|---|
| Input | The fused candidate list |
| Output | A re-scored, re-ordered final list |
| How | BGE-Reranker-v2-m3, a self-hosted cross-encoder, re-scores the candidate pool with full cross-attention instead of dot-product similarity — maximizes precision in what gets passed to the agent |

## Output Contract
Each item returned to the Research Agent carries:
- chunk text
- `chunk_id` (joins to `chunks` in Postgres, and to its vector in Turbovec)
- source `document_id` and a human-readable reference (filename/page, or
  function/file for code)
- relevance score

This is exactly what the Research Agent needs to attach a citation without
a separate lookup step.

## Success Criteria
- Returned chunks are scoped to the requesting `workspace_id` — no
  cross-workspace leakage.
- Every returned chunk includes a usable citation reference.
- Reranking measurably improves the order over the raw fused list (verified
  via the integration test described in `conventions.md`).

## Out of Scope (MVP)
Semantic cache short-circuit (Redis), permission-aware scoped retrieval
(RBAC), and any retrieval step triggered by a Planner or Critic — all
Phase 2 per `PRD.md`.
