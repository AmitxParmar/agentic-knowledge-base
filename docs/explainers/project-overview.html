The Agentic Research Workspace

An agentic RAG knowledge base: you upload PDFs, code repos, or audio files, then ask questions and get answers where every claim cites the exact chunk it came from. The MVP deliberately ships one agent — a LangGraph Research Agent — while the V1 multi-agent design (Planner, Critic, caches, memory) stays parked behind the PRD's Non-Goals wall.

API: FastAPI · LangGraph UI: Next.js 16 · React 19 · TanStack AI Store: Postgres + in-process Turbovec Queue: Redis · arq Models: Groq → OpenRouter (Model Gateway)

The shape of the system

One loop: upload → ask → cited answer

Everything in the MVP serves a single vertical slice. Documents flow down the ingestion lane into searchable storage; questions flow down the research lane out the other side as answers. Dashed boxes are V1 features that exist in the architecture doc but are explicitly deferred by the PRD — building any of them now without a justifying metric is, in the project's own words, "a process violation, not a shortcut."

Locked technology choices

Decisions already made — don't relitigate

ADRs exist so nobody re-derives a settled choice mid-PR. A change that contradicts an ADR is rejected without debate; the escape hatch is a new ADR, never quiet divergence.

ADRChoiceWhat it buys
ADR-001LangGraph for the Research Agent An explicit ReAct state graph: the loop (reason → retrieve → answer) and its iteration cap live in the graph, not in hand-rolled glue.
ADR-002Turbovec in-process vector index Postgres stays the source of truth; vectors rebuild from PG on startup. Dense scoring runs inside the kernel with a metadata allowlist. No second database server, no pgvector.
ADR-003Model Gateway Every chat/embed/rerank call goes through src/shared/model_gateway.py. Feature code never imports a provider SDK — swapping Groq for OpenRouter (or local LM Studio) touches one file.
ADR-005TanStack AI frontend runtime useChat owns message/loading/error state on the client. Phase 4 chose Option B: the backend speaks the AG-UI protocol over a plain SSE endpoint (/api/research/chat), so no hand-rolled WebSocket state machine survives.
PRD Non-Goals — the boundary that keeps the MVP small

What is deliberately not built yet

The frozen V1 design is a three-agent system with semantic caching, plan reuse, memory, and nightly evaluation. The MVP builds the smallest slice that proves the core value. Each of these is real work — it's just scheduled behind evidence that it's needed.

Agents

  • Planner Agent — no multi-hop task decomposition
  • Critic / reflection loop — added once failure rates are measured
  • MCP tool layer (web/GitHub/filesystem) — retrieval-over-uploads only

Caches & memory

  • Plan cache — nothing to reuse without a Planner
  • Semantic cache (Redis) — premature before usage volume
  • Working / semantic memory, conversation summaries

Ops & safety

  • RBAC, scoped retrieval, secret management (single-tenant MVP)
  • LLM guardrails — added after real misuse is observed
  • RAGAS/DeepEval nightly eval, Prometheus + Grafana
Governance

Decision authority — highest wins

When a request conflicts with a doc, the conflict gets flagged — not silently resolved toward whichever is convenient. This is the ladder, top rung first.
